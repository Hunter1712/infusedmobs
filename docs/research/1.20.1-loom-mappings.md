# 1.20.1 Loom mappings research

We need `:1.20.1` (obfuscated, Java 17) to compile the same MojMap `common` sources as `:common`/`:26.2` (unobfuscated, Java 25). We decided `:1.20.1` applies `net.fabricmc.fabric-loom-remap` with `mappings loom.officialMojangMappings()` plus `modImplementation` loader/Fabric API `0.92.0+1.20.1`, and every 1.20.1-divergent API goes behind a same-FQN per-version shim — the exact `:1.21.1` recipe from `1.21.1-loom-mappings.md`, because 1.20.1 sits on the same (obfuscated) side of Loom's unobfuscation boundary and the same per-project obfuscation-mode rules apply.

All 1.20.1 MojMap claims below are from the cached layered mappings (`~/.gradle/caches/fabric-loom/1.20.1/loom.mappings.1_20_1.layered+hash.2198-v2/mappings.tiny`, line numbers cited); all Fabric API 0.92.0 claims from `javap` on the nested module jars inside `fabric-api-0.92.0+1.20.1.jar`.

## 1. What 1.20.1 shares with 1.21.1 (no new work)

- `ResourceKey#location()` returning `ResourceLocation` (line 14301ff); `EntityType.ZOMBIE`, `BuiltInRegistries.ENTITY_TYPE.getKey` returning `ResourceLocation`; `ResourceLocationArgument` with `id()`/`getId` (line 3030); `Commands.LEVEL_GAMEMASTERS` + `CommandSourceStack.hasPermission(int)` + `sendSuccess(Supplier, boolean)` — so `DimensionHelper`, `CommandArgHelper` and all of `InfusedMobsCommand` (including `ResourceArgument.resource(buildContext, Registries.ENTITY_TYPE)` + `getSummonableEntityType`, line 2964ff) are verbatim copies of the 1.21.1 shims.
- `EntityType` has no 2-arg `create(Level, reason)` (`EntitySpawnReason` occurs 0 times); plain 1-arg `create(Level)` is used by `SpawnHelper` and `CommandArgHelper.createForCommand`, same as 1.21.1.
- `MobEffects` field names match 1.21.1 (`MOVEMENT_SLOWDOWN`, `DAMAGE_RESISTANCE`, `DAMAGE_BOOST`, `MOVEMENT_SPEED`, plus `POISON`/`WITHER`/`WEAKNESS`/`REGENERATION`).
- `SavedData` NBT read API matches 1.21.1 (`contains`/`getCompound`/`getAllKeys`/`getString`/`getList(key, TAG_STRING)`/`Tag.getAsString`); `setDirty()` no-arg exists.

## 2. Where 1.20.1 diverges from 1.21.1 (the actual #7 work)

- Effects are raw `MobEffect`, not holders: `MobEffectInstance` constructors take `(MobEffect, int, int)` and `(MobEffect, int, int, boolean, boolean, boolean)` only. Hence effect handles are version-neutral `Object` — `common` `AbilityRegistry` routes every effect (including `poison`/`wither`/`weakness`/`regeneration`) through `AbilityHelper` accessors; 26.2/1.21.1 shims cast to `Holder<MobEffect>`, the 1.20.1 shim to `MobEffect`.
- `LivingEntity` has no `hurtServer`; damage uses `Entity#hurt(DamageSource, float)` (line 27513, inherited) — same call shape as the 1.21.1 shim.
- Armour uses generic `<T extends LivingEntity> hurtAndBreak(int, T, Consumer<T>)`, so the 1.20.1 shim passes `player` directly (no `ServerLevel`).
- Igniting uses `setSecondsOnFire(int)` — `igniteForSeconds` does not exist — so Hellfire goes through `AbilityHelper.ignite` (1s granularity on 1.20.1).
- Persistence uses `DimensionDataStorage#computeIfAbsent(Function, Supplier, String)` (line 60701ff, in the `world.level.storage` package) with single-arg `save(CompoundTag)` — no `Factory`, no `SavedDataType`, no `HolderLookup.Provider`.
- Gamerule shape matches 1.21.1 exactly: vanilla `GameRules` with `Key`/`Type`/`Category.MOBS` + `getBoolean(Key)` (line 43087ff), Fabric `GameRuleRegistry.register(String, Category, Type)` + `GameRuleFactory.createBooleanRule(boolean)` (javap on the 0.92.0 nested jars) — so `ModGameRules` is a verbatim copy of the 1.21.1 file and datapacks toggling `infusedmobs:enabled` behave identically.
- `ServerLivingEntityEvents` in 0.92.0 has `ALLOW_DAMAGE`/`ALLOW_DEATH`/`AFTER_DEATH`/`MOB_CONVERSION` but NO `AFTER_DAMAGE` (javap). `AFTER_DEATH` matches common's `(LivingEntity, DamageSource)` handler, so `MobDeathTrigger` is untouched; HURT registration goes through the new `HurtTriggerHelper` seam (`AFTER_DAMAGE` on 26.2/1.21.1, `ALLOW_DAMAGE` adaptor on 1.20.1 with pre-mitigation amount and `blocked=false` — exact parity is #9).

## 3. `:1.20.1` dependencies block

```groovy
dependencies {
    minecraft "com.mojang:minecraft:${project.minecraft_version}"
    mappings loom.officialMojangMappings()
    modImplementation "net.fabricmc:fabric-loader:${project.loader_version}"
    modImplementation "net.fabricmc.fabric-api:fabric-api:${project.fabric_api_version}"
}
```

- Same block as `:1.21.1` with that overlay's versions. `modImplementation` (not `implementation`) remaps loader/FAPI to `named` so no `class_*` intermediary names leak. `enableTransitiveAccessWideners = false` is kept (FAPI access wideners target intermediary, same rationale as before).
- Local builds accept either the system `gradle` binary or `./gradlew` — both run the same scripts; the wrapper stays canonical for CI. (The wrapper distribution was not in the local cache, so first `./gradlew` run downloads Gradle 9.6.1.)
